# 12.07 — Diagnoza: dlaczego nowy run (17 epok) jest gorszy od starego (37 epok)

**TL;DR:** Jedyna zmiana treningowa między runami to dodanie straty **`mil_radial_spread_loss`
(`mil_radial_weight=0.5`)**. To ona (a) rozmazała mapy uwagi MIL i (b) zdegradowała fine-tuning → gorsza
val_mae i wcześniejszy early-stop. Usuwamy ją.

## Porównywane runy
- **Stary (DOBRY):** `outputs/11.07/` — 37 epok (realnie), best val_mae **0.792** @e27, test **MAE 0.789**,
  Bias −0.039. Mapy uwagi sensowne.
- **Nowy (ZŁY):** `outputs/12.07/` — 17 epok, best val_mae **0.824** @e7, test **MAE 0.838**, Bias −0.14.
  Mapy uwagi „bez sensu".

## Kontrolowany dowód (jedna zmienna)
`git diff 80d76a0 4de46cd` dla plików wpływających na trening (config / trainer / model / dataset) pokazuje
**jedną zmianę merytoryczną**:
```
+ mil_radial_weight: 0.5   # + obsługa mil_radial_spread_loss w trainerze/modelu
```
Brak zmian LR, głowic, `mil_count_loss`, augmentacji, splitu. Czysty eksperyment z jedną zmienną.

- Stary run systematycznie obniżał najlepszy wynik do e27 (0.828→0.809→0.792); podłoga szumu val_mae 0.79–0.85.
- Nowy run utknął na 0.824 @e7 i już nigdy nie zszedł niżej; podłoga szumu wyżej (0.84–0.98) → po 10 epokach
  bez poprawy early-stop @17.
- `mil_radial` liczbowo jest **znikome** (0.0004–0.008), ale to nie znaczy „nieszkodliwe": jego gradient płynie
  do **współdzielonego backbone** po odmrożeniu i przeciąga cechy w stronę „rozłóż aktywność promieniowo", co
  koliduje z dyskryminacją wieku (na której opiera się CORAL).

*(Uczciwa uwaga: część różnicy w momencie early-stopu to też czułość na szum — stary run dociągnął do 0.792
w e27 tuż przed limitem patience. Ale gorsza podłoga val_mae i rozmyte mapy są realne i wynikają z radial.)*

## Mechanizm „map bez sensu"
1. `mil_radial_spread_loss` z definicji **rozpycha aktywne patche do sztucznego celu wariancji**
   (`0.10 + 0.03·wiek`), niezwiązanego z realnym położeniem przyrostów → mapa MIL robi się rozmyta/„rozciągnięta"
   zamiast skupionej. Renderowanie map (`compute_patch_importance` → prob MIL → heatmapa) się NIE zmieniło,
   więc różnica pochodzi wyłącznie z tego, czego nauczyła się głowica MIL.
2. Model jest mniej douczony (best @e7 zamiast @e27) → mapa dodatkowo zgrubna.

## Naprawa
Usunąć radial-spread **w całości** (żadnego martwego kodu); trening wraca do znanego-dobrego CORAL+MIL
(jak run 37-epokowy: ~0.79 MAE, sensowne mapy). Reszta zmian tej sesji jest post-hoc i zostaje: karty
2-głowicowe, Grad-CAM, uwaga CLS, macierz pomyłek, sekcja OpenCV, pruning checkpointów, konsolidacja outputów.

**Lekcja na przyszłość (Kierunek B):** lokalizacja przyrostów **nie może degradować głowicy wieku** —
kolejne próby muszą być odsprzęgnięte od współdzielonego backbone i oparte na sprawdzonych metodach.

### Metody znalezione w literaturze (nie zgadujemy)
- **Otolity — nadzorowana lokalizacja (standard domenowy):** detekcja/segmentacja przyrostów wzdłuż osi
  odczytu, Mask R-CNN + U-Net. *Fish age reading using DL for object-detection and segmentation*, ICES JMS 2024
  — https://academic.oup.com/icesjms/article/81/4/687/7614790
- **Interpretowalność werdyktu wieku (nie lokalizacja):** *Explaining decisions of DNNs used for fish age
  prediction* (Grad-CAM/saliency) — https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7304622/ (u nas: Grad-CAM + uwaga CLS).
- **Słaby nadzór samą liczbą (crowd counting = najbliższy analog):** mapa gęstości, całka≈liczba, piki=obiekty;
  samo regresowanie całki do liczby zawodzi → potrzeba **strat spójności**:
  - Wan & Chan, *Generalized Loss Function for Crowd Counting and Localization*, CVPR'21 — http://visal.cs.cityu.edu.hk/static/pubs/conf/cvpr21-generalizedloss-www.pdf
  - *Towards using count-level weak supervision for crowd counting* — https://www.sciencedirect.com/science/article/abs/pii/S0031320320304192
  - *Optimal Transport Minimization — Crowd Localization on Density Maps*, CVPR'23 — https://openaccess.thecvf.com/content/CVPR2023/papers/Lin_Optimal_Transport_Minimization_Crowd_Localization_on_Density_Maps_for_Semi-Supervised_CVPR_2023_paper.pdf
  - *Deeply-Supervised Density Regression for Automatic Cell Counting* — https://arxiv.org/pdf/2011.03683
- **Klasyka słojów (analog dendro):** profil intensywności + piki / szablony B-spline (Troadec — deformable
  template; Dendro-AutoCount — pith + peak analysis) — u nas jako interaktywny reference OpenCV (sekcja H).
