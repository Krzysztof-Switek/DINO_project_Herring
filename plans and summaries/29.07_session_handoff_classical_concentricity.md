## Decisions locked + what shipped
- **New classical-only scoring mechanism** in `C:\Users\kswitek\Documents\DINO_project_Herring\src\ring_extraction.py`: `_classical_concentricity_variance`, `_classical_concentricity_factor`, `_scored_classical_cluster` — a post-hoc (non-trained) multiplicative penalty on `_cluster_by_radius_with_arcs` clusters, gated by new `classical_concentricity_weight` (default `0.0` = off, zero behavior change). Wired into `fuse_increments` (`"classical"`/`"consensus"`/`"dp"` branches) and `_merge_clusters`; density's own scoring is untouched.
- **Correctness fix (user-caught, substantive, not cosmetic):** the first version compared a candidate ring's signal across ALL 48 rays around the full circumference — biologically wrong, since real increments are typically expressed strongly on only part of the circumference. Fixed by adding `_arc_band` (full geometric span of the winning contiguous arc, including gap positions — distinct from `_best_arc_members`, which only counts rays that individually cleared the peak threshold) and threading an optional `ray_indices` parameter through `_classical_concentricity_variance`/`_factor`/`_scored_classical_cluster`, restricting the variance check to the arc's own band instead of the full 360°. `assign_rays_to_clusters` now also returns a `"band"` key.
- **New config surface:** `CandidatesConfig.classical_concentricity_weight` in `C:\Users\kswitek\Documents\DINO_project_Herring\src\config.py` + `C:\Users\kswitek\Documents\DINO_project_Herring\configs\config.yaml` (both default `0.0`).
- **Pipeline wiring:** `C:\Users\kswitek\Documents\DINO_project_Herring\scripts\run_pipeline.py` reads the config and threads it through the card-generation loop and `dp_walkthrough_data`.
- **New visualization:** `render_arc_cluster_overlay` in `C:\Users\kswitek\Documents\DINO_project_Herring\src\visualization.py` — draws which rays merge into a winning arc (thick) vs scattered same-cluster support (thin), directly on an otolith photo, per explicit user request to see the existing arc mechanism, not just have it described.
- **Tests:** ~20 new tests across `tests\test_ring_extraction.py` and `tests\test_stage10_visualization.py`, including tests that specifically prove the segment-restriction fix (disagreement outside the arc band is ignored). Full suite: **404/404 passing** (last run this session).
- **Validation result:** unlike E9's own w=0.1 (a flat null result), this mechanism shows a real, non-null signal on the 30-card sample — after the fix, `mean_dist` improves from ~206px (weight=0) to ~190px around weight≈4.6–9.3, with `frac_cards_changed` rising smoothly 0%→~57% as weight increases. Not yet validated on a larger sample; default weight stays `0.0`.
